# 核验与写作铁律

这些规则是本刊可信度的全部来源。**任何一条与「多出点内容」冲突时，都是规则赢。**

## 一、来源与核验

1. **不信检索索引**。Google/Bing/arXiv 检索页的摘要、作者、单位一律不作数。每条进正文的论文必须
   `curl` 原文核：arXiv → `https://arxiv.org/abs/<id>`；期刊 → Crossref `https://api.crossref.org/works/<doi>`；
   必要时读 PDF 致谢/脚注确认机构。
2. **作者与单位逐位核**。核不到单位写「待确认」。**绝不以人名、口音、合作网络猜单位或国别。**
3. **每个数字必须能追到一个 URL**。追不到的数字不写。
4. **一手优先**。论文 > 官方新闻稿 > 行业媒体转载。营销落地页、专利、供应商目录**不作为论文来源**。
5. **时间窗内**。窗口 = 上期日期之后至本期日期。窗外但高价值的可收，但必须标「（窗口外补记）+ 原始日期」。
6. **同行评审 vs 预印本**必须标明。预印本一律写「arXiv 预印本（YYYY-MM）、未同行评审」。

## 二、事实 / 前瞻 分离

7. **厂商宣称**的性能数字，写成「厂商宣称 …」，不得写成既成事实。
8. **分析师 / 市场规模 / 渗透率预测**（TrendForce、MarketsandMarkets、Omdia、Dell'Oro 等）
   **只能进第五节「⚠️ 前瞻 / 分析师数字（不作既成事实）」**，不得混入前四节。
9. **未发布产品**写成「预告 / 将出产品的信号，非已发货」，并注明揭晓日期。
10. 口径变化（例如渗透率从 47% 改为 53%）要**显式写出是哪家哪次更新**，不要静默替换。

## 三、去重与连续性

11. 起草前必读 `drafts/reported-index.md`。命中已报**标题 / arXiv id / DOI / URL** 的候选 = 不再重复报道；
    只有出现**实质进展**（同行评审接收、硬件实测、规格揭晓）时，才以一句话「进展更新」提及并注明原报期数。
12. 长期缺口要**连续计数**：「连续第 N 期仍缺」。缺口消失了也要显式说明补上了。
13. 「开放问题 / 下期」里挂的账，下一期必须逐条回应（补上了 / 仍缺 / 已放弃并说明原因）。

## 四、写作

14. **不凑数**。内容稀的一周就写薄的一期，并在「方法与局限」里如实说明本期短板。
15. 论文卡固定五段：**研究团队 / 技术介绍（含性能）/ 技术优势（先进性）/ 技术局限 / 来源**。
16. 正文中文；专业术语首次出现给「中文（English）」或「English 中文」对照，之后可只用一种。
17. 数字带单位，温度 `°C`、压降 `kPa`、功率 `kW`；相对量写清基准（「相对常规设计 −72.8%」）。
18. 不写形容词式评价（「革命性」「颠覆」）。先进性用**与现有方法的具体差别**说明。
19. 署名固定：`*—— Sage · 散热方案周报第 N 期（待核验稿）*`。

## 五、流程

20. **绝不直接推 `main`**。一律 `briefing/<日期>` 分支 + PR，交人工核验后合并。
21. 调 `scripts/ingest_briefing.py` 必须带 `--no-push`。
22. 推分支前跑 `mkdocs build --strict`，构建不过不开 PR。
23. PR 正文必须列出**逐条来源**与**本期未核 / 待确认项**，方便人工只复核风险点。
